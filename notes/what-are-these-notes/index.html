    What Are These Notes

    These notes are an interconnected web of roughly “atomic” or “evergreen” notes inspired by the zettelkasten method. I write them in the org markup language, and I edit and navigate them in Emacs. I wrote an exporter built into my custom site generator to view them on my website because

    1. I like looking at them in the browser
    2. Maybe someone else will like them and will tell me they’re cool, in which case my deep desire for the radiant sort of conceited happiness that comes only from the validation and attention of other bipedal paleolithic animals might be sated for one day more.

    This system lets me

    • create new notes quickly
    • find existing notes with lazy search of human-readable subject matter
    • write, edit and navigate notes in one place (Emacs)
    • use the same LaTeX style-sheets in my LaTeX documents and my notes
    • export my notes to a variety of formats
    • change any aspect of my system to my heart’s content.

    If you find mathematical mistakes, factual errors or bad opinions in here please tell me. If you do not like the note-taking system itself then do not tell me.

    If you like this system and want to use it, you probably shouldn’t, particularly if you have actual work to do. There are many other tools out there that achieve basically the same thing and are superior in real ways:

    • Obsidian will let you take Markdown notes with backlinks and a graph visualization of your notes.
    • Roam Research is similar and is targeted specifically at researchers
    • Forester is a beacon of singular beauty, a labor of love wrought into existence by a bunch of category theory wizards seeking to understand the secret structure of notes themselves.

    I have never used Obsidian or Roam Research, and I stopped using Forester after about a year, but I know productive members of society who use and enjoy all these tools.

    About slipbox/zettelkasten/evergreen notes

    Traditional linear notes function primarily as a storage mechanism. You write them once, in some sort of order, and then revist them only to recall, never to revise. Evergreen notes, on the other hand, evolve and grow over time. With a slipbox/linking system these notes can reference each other, and connections between notes thereby represent relationships between ideas. Over time, the collection of notes resembles something similar to the way a human brain processes ideas, and hopefully it can even help you discover connectios between concepts you couldn’t see yourself. Atomicity, the idea that each note should capture one concept completely, helps this process along.

    That’s the theory anyway. It seems like most people who use this sort of note taking system never end up writing about the thing they set out to study in the first place, and instead end up writing pages and pages about slipbox-systems instead.

    How I ended up here

    My personal note system is an amalgamation of various org-mode extensions (org-node principle among them) built on top of Doom Emacs. I got here because

    • In 2022 I found the late Giles Castel’s incredible guide to live-TeXing in Vim, and promptly started using it to take notes during lectures in my masters.
    • In 2023, about a year into my Ph.D., I started using the Franklin static-site generator written in Julia. It’s fairly easy to extend, and extend it I did. I started writing notes I wished to distribute, things like seminar notes, in Franklin markdown with a laundry list of easily-breakable custom export rules.
    • In 2024 a friend told me about Forester and I thought it was awesome. Frustrated with my Markdown setup, I moved over completely to Forester.
    • Forester is quite formal and encourages the practice of transcluding notes. Because of this, I often found myself in a loop: I’d create a new note to write about something relevant to my research, but quickly find it relied on another, more basic concept which didn’t yet exist in my forest. So I’d create a new note, start writing, and the process would repeat. I would sometimes have a 10-file backlog of file to write before I could return back to the original note. In theory this sort of thing should happen less frequently as the forest grows, in practice I found that it did not.
    • I tried extending Forester myself, but I didn’t know OCaml well and had actual work to do, so I eventually gave up. It’s sad because I think Forester is wonderful and want to go back someday.
    • I heard about Roam Research and the org-roam Emacs extension it inspired. That grew into the homegrown Emacs system I use today.

    The system I landed on isn’t perfect but, being entirely homegrown outside of a few external Emacs packages, it has the advantage of being endlessly customizable and will therefore continue to evolve. This is also the reason I doubt it’d be particularly useful to anyone else, but if you are still interested in using it for some reason then I can separate out the generalizable bits.
